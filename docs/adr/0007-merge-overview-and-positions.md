# ADR 0007 — 資產總覽與持倉列表合併為單頁

**狀態**：已採納｜**日期**：2026-08-13

## 背景

原 Sitemap 規劃「資產總覽」與「持倉列表」為兩個分頁，底部 Tab Bar 共 4 項。

但使用者情境是「通勤或睡前快速查看部位」。這種情境下打開 App 想看的就兩件事：**總共有多少錢、哪一檔在賺賠**。

分成兩個分頁，等於強迫使用者為了看最關心的資訊多點一次。

## 決策

**合併為單一路由 `/portfolio`。** 上半部是總覽卡片（總資產、今日損益、走勢曲線），往下捲直接接持倉列表。

底部 Tab Bar 從 4 項減為 3 項：**資產 / 明細 / 下單**。

**連帶決策**：持倉不另開個股詳情頁，點擊列展開顯示成本、市值、報酬率即可。

## 替代方案

| 方案 | 捨棄理由 |
|---|---|
| 維持兩個分頁 | 使用者要看核心資訊需多點一次；多一組載入／空／錯誤狀態要實作與測試 |
| 合併但持倉另開詳情頁 | 展開列已足夠承載資訊；獨立路由要多做一組狀態處理，收益低 |

## 後果

**正面**

- 符合真實使用情境，是可主動說明的產品判斷
- 少一個路由、少一組載入／空／錯誤狀態、少一份測試
- 底部 Tab 3 項，手機視覺更乾淨

**負面**

- `/portfolio` 頁面變長，需注意首屏可見內容的優先序（總資產必須在首屏）
- 三個 API（summary、positions、snapshots）需平行載入且各自渲染，不能等彼此
- 頁面內需獨立的區塊級 error boundary —— 走勢圖掛掉不該讓持倉列表消失
