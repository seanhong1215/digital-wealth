# 03 — 資料呈現層規範

> 情境 I 產出｜前端資料處理與顯示規則
> 版本 0.1｜2026-08-13｜維護者：Shawn Ben

> **核心信念：原始資料是給機器看的，經過處理的資訊才是給人看的。**
>
> 後端回傳的是「正確的資料」，本文件定義如何把它變成「使用者看得懂的資訊」。

---

## 資料 Gap 分析

後端回什麼、使用者實際需要看到什麼、中間差了哪些處理。

| 原始欄位 | 原始值範例 | 使用者需要看到 | 處理方式 |
|---|---|---|---|
| `cashBalanceCents` | `5000000` | `NT$ 50,000` | `formatMoney()` |
| `priceCents` | `108500` | `1,085.00` | `formatPrice()`（股價保留小數） |
| `quantity` | `1000` | **`1 張`**（或 `1,000 股`） | `formatShares()` ← 台股特有 |
| `quantity` | `500` | **`500 股`**（零股） | 同上，未滿一張顯示股數 |
| `priceCents` + `prevCloseCents` | `108500`, `107000` | **`▲ +15.00 (+1.40%)`** | 前端計算 ＋ 三重編碼 |
| `avgCostCents` + 即時報價 | `105000`, `108500` | **`未實現 +35,000 (+3.33%)`** | 前端計算（隨報價變動） |
| `occurredAt` | `2026-08-13T01:23:45Z` | `今天 09:23` / `8/10` | `formatRelativeTime()` |
| `status` | `"FILLED"` | `✓ 已成交` | 狀態映射表 |
| `type` | `"FEE"` | `手續費` | 型別映射表 |
| `amountCents` | `-108654600` | `-NT$ 1,086,546` | 正負號 ＋ 顏色 |
| `feeCents` + `taxCents` | `154600`, `0` | `手續費 NT$ 1,546` | 分開顯示，讓使用者知道錢花在哪 |
| WS 訊息時間 | `at: "...45.678Z"` | **`即時` / `延遲` / `報價中斷`** | 新鮮度狀態機 |

### 三個最需要處理的 Gap

**1. 張／股的換算（台股特有）**

台股一張 = 1000 股。使用者說「買一張台積電」，不說「買一千股」。但零股交易時又是以股計算。

```
1000 股  → "1 張"
3000 股  → "3 張"
1500 股  → "1 張 500 股"
500 股   → "500 股"
```

後端一律存**股數（整數）**，換算是純呈現邏輯。

**2. 未實現損益必須前端算**

後端不會回傳這個欄位（見 `02-backend.md`）。前端拿 `avgCostCents`（成本）＋ WebSocket 最新報價自行計算：

```
未實現損益 = (現價 − 平均成本) × 股數
未實現報酬率 = (現價 − 平均成本) / 平均成本
```

**3. 報價新鮮度必須可見**

一個不會動的數字，使用者無法分辨是「市場沒成交」還是「連線斷了」。這是金融介面最容易被忽略、也最容易被面試官問到的地方。

## 格式化規範

所有格式化函式集中於 `web/shared/lib/format.ts`，金額運算集中於 `shared/money.ts`。

### 金額

| 情境 | 規則 | 範例 |
|---|---|---|
| 一般金額 | 千分位，**不顯示小數**（台股金額以元為單位） | `NT$ 1,086,546` |
| 股價 | 保留 2 位小數（依 tick size） | `1,085.00` |
| 負數 | **前置負號**，不用括號 | `-NT$ 12,345` |
| 損益 | **一律顯示正負號**（正數也要 `+`） | `+NT$ 35,000` |
| 幣別 | 前綴 `NT$`，與數字間一個半形空格 | `NT$ 50,000` |

### 邊界條件 ★

**這張表是本文件最重要的部分。** 邊界沒處理好，畫面就會出現 `NT$ NaN` 或 `undefined`。

| 情況 | 顯示 | 理由 |
|---|---|---|
| `null` / `undefined` | `—`（em dash） | 「沒有這個資料」 |
| `0` | **`NT$ 0`**，不是 `—` | 「餘額是零」與「不知道餘額」是不同的事 |
| 損益為 `0` | `NT$ 0`，顏色用 `flat`（灰） | 不用漲跌色 |
| 負零（`-0`） | 正規化為 `0` | JS 的 `-0` 會顯示成 `-0` |
| 超過安全整數 | 顯示 `—` ＋ 開發環境拋錯 | 見 `02-backend.md` 的 `MAX_SAFE_INTEGER` 說明 |
| 空陣列 | 空狀態元件，不是空白區塊 | — |
| 超長標的名稱 | 單行省略 `…` ＋ `title` 屬性 | 不換行破壞表格對齊 |

### 日期時間

**一律使用相對時間**，因為使用者關心的是「多久以前」不是「幾月幾號」。

| 距今 | 顯示 | 範例 |
|---|---|---|
| < 1 分鐘 | `剛剛` | — |
| < 1 小時 | `N 分鐘前` | `23 分鐘前` |
| 今天 | `今天 HH:mm` | `今天 09:23` |
| 昨天 | `昨天 HH:mm` | `昨天 14:05` |
| 7 天內 | `週X HH:mm` | `週三 10:31` |
| 今年內 | `M/D` | `8/10` |
| 跨年 | `YYYY/M/D` | `2025/12/28` |

> **明細列表的時間一律用相對格式，但點開詳情要顯示完整時間戳。** 稽核情境需要精確到秒。

### 數量與百分比

| 項目 | 規則 | 範例 |
|---|---|---|
| 股數 | 千分位 ＋ 張／股換算 | `1 張 500 股` |
| 百分比 | 2 位小數 ＋ 正負號 | `+1.40%` |
| 百分比為 0 | `0.00%`，灰色 | — |
| 分母為 0 | `—`，不顯示 `Infinity` | 成本為 0 時的報酬率 |

### 數字排版

**所有數字欄位一律 `font-variant-numeric: tabular-nums`。**

等寬數字讓每個數字佔用相同寬度，表格中的金額才會**小數點對齊**。沒有這個設定，`1,085.00` 和 `999.00` 在視覺上會歪掉。這是金融介面的基本要求，也是最容易被忽略的細節。

## 狀態推導邏輯

### 1. 漲跌狀態（`PriceDirection`）

```
現價 vs 昨收（或 現價 vs 平均成本）
        │
        ├─ 差值 > 0 ──► 'up'    紅色 ＋ ▲ ＋ 正號    ← 台股紅漲
        ├─ 差值 < 0 ──► 'down'  綠色 ＋ ▼ ＋ 負號    ← 台股綠跌
        └─ 差值 = 0 ──► 'flat'  灰色 ＋ — ＋ 無號
```

**三重編碼是硬性規範：顏色 ＋ 符號 ＋ 正負號，三者缺一不可。**

理由有兩層：

1. **無障礙** —— 紅綠色覺辨識障礙在男性約佔 8%。純靠顏色的話，這群人看到的是「兩個一樣深的灰」
2. **次要使用者** —— 55 歲以上族群對低對比顏色的辨識力下降

> **Token 命名用 `up` / `down` 而非 `red` / `green`。** 台股紅漲綠跌，美股相反。命名成語意，未來支援美股情境只需改 token 對應值，不用改任何元件程式碼。

### 2. 報價新鮮度（`QuoteFreshness`）

```
                收到新報價
        ┌──────────────────────┐
        ▼                      │
    ┌────────┐   > 5 秒未更新  ┌────────┐
    │  live  │ ───────────────►│ stale  │
    └────┬───┘                 └───┬────┘
         │                         │
         │    WebSocket 連線中斷    │
         └───────────┬─────────────┘
                     ▼
             ┌──────────────┐
             │ disconnected │
             └──────────────┘
```

| 狀態 | 視覺表現 | 使用者理解 |
|---|---|---|
| `live` | 數字正常色，更新時背景閃爍 150ms | 「這是即時的」 |
| `stale` | 數字轉為次要色，旁邊小字 `延遲` | 「有點舊了但還在連線」 |
| `disconnected` | 頂部橘色橫幅「報價中斷，顯示最後價格」＋ 數字加上灰底 | 「這是舊資料，別依賴它下單」 |

> **`stale` 與 `disconnected` 是不同的事，實作時最容易混淆。**
>
> - `stale`：連線正常，但這檔標的沒成交（冷門股很常見）
> - `disconnected`：WebSocket 斷了，**所有**標的都收不到
>
> Demo 控制台的 `quote-disconnect` 故障對應後者；`QuoteTrend: 'frozen'` 對應前者。

**降級原則：報價斷了，其他功能仍要能用。** 持倉、明細、下單都不依賴 WebSocket。

### 3. 委託狀態（`OrderStatus`）

| 後端值 | 顯示文字 | 圖示 | 顏色 |
|---|---|---|---|
| `PENDING` | `處理中` | 旋轉指示器 | 次要色 |
| `FILLED` | `已成交` | `✓` | 成功色 |
| `REJECTED` | `已拒絕` | `✕` | 錯誤色 ＋ 顯示原因 |

> **`REJECTED` 必須顯示原因。** 只說「失敗」是最糟的錯誤處理 —— 使用者不知道該改什麼。原因來自後端的 `reject_reason` 對應到錯誤碼表。

### 4. 交易類型（`TransactionType`）

| 後端值 | 顯示 | 金額方向 | 顏色 |
|---|---|---|---|
| `BUY` | `買進` | 負（扣款） | 中性 |
| `SELL` | `賣出` | 正（入帳） | 中性 |
| `FEE` | `手續費` | 負 | 次要色 |
| `TAX` | `證交稅` | 負 | 次要色 |
| `DIVIDEND` | `股利` | 正 | 成功色 |
| `DEPOSIT` | `入金` | 正 | 中性 |
| `WITHDRAWAL` | `出金` | 負 | 中性 |

> **買進／賣出本身不用漲跌色。** 漲跌色專門保留給「價格變動」。買進不是「跌」，賣出不是「漲」，混用會讓使用者誤讀。這條規則很容易被違反，要寫進元件註解。

## 視覺呈現建議

### 資產走勢曲線

| 項目 | 建議 | 理由 |
|---|---|---|
| 圖表類型 | **折線圖 ＋ 漸層填充** | 面積圖強調「累積量」，資產總值是「狀態」不是累積 |
| 資料點 | 近 30 日，每日一點 | 讀 `portfolio_snapshots` |
| 顏色 | 期間報酬為正用漲色、為負用跌色 | 讓趨勢一眼可辨 |
| Y 軸 | **不從 0 開始** | 資產在 100 萬上下波動，從 0 起會壓扁成一條直線 |
| 互動 | 觸控／滑鼠移動顯示當日數值 | 手機優先，要支援觸控 |
| 空狀態 | 少於 2 個資料點時顯示「資料累積中」 | 新帳戶情境 |

> **Y 軸不從 0 開始是刻意的取捨。** 一般資料視覺化的準則是「柱狀圖必須從 0 開始，否則誇大差異」，但**折線圖表示的是變化趨勢，從 0 開始反而看不出東西**。金融走勢圖業界慣例都不從 0 起。這個取捨值得在 README 提一句。

### 資產配置

| 項目 | 建議 |
|---|---|
| 圖表類型 | **橫向堆疊條** 優於圓餅圖 |
| 理由 | 標籤好放（中文股名放圓餅外圍會擠）、手機寬度利用率高、小佔比項目仍可辨識 |
| 分組 | 前 5 大持倉 ＋ 「其他」 ＋ 現金 |
| 顏色 | 使用**中性色階**（靛藍 200→700），不用漲跌色 |

> 配置圖在可砍清單第 1 位 —— 走勢曲線已展示圖表能力，這是重複訊號。若要做，橫條比圓餅便宜。

### 持倉列表

| 項目 | 建議 |
|---|---|
| 每列資訊層級 | 主：股名 ＋ 現價 ＋ 漲跌｜次：股數 ＋ 未實現損益 |
| 展開 | 點擊展開顯示成本、市值、報酬率，**不另開頁面** |
| 排序預設 | 市值由大到小 |
| 報價更新 | **只重繪變動的那一列**，背景閃爍 150ms |

### 交易明細

| 項目 | 建議 |
|---|---|
| 虛擬滾動 | TanStack Virtual，`overscan: 5` |
| 分組 | 依日期分組，黏性日期標題（sticky header） |
| 每列 | 左：類型 ＋ 標的｜右：金額 ＋ 時間 |
| 載入更多 | 捲到距底部 300px 觸發，顯示骨架列 |

## 異常與警示策略

### ⚠️ 合規紅線：只做資訊提示，絕不做投資建議

**這是本專案最重要的一條規則。**

| ✅ 可以說 | ❌ 絕對不可以說 |
|---|---|
| 「台積電佔投組 45%」 | 「建議分散持股」 |
| 「本月報酬 −8.2%」 | 「considering 停損」 |
| 「餘額不足，尚缺 NT$ 12,000」 | 「建議先賣出部分持股」 |

即使是虛構品牌的作品集，**投資建議涉及金管會的投顧特許業務**。一個技術主管看到你的 demo 在給買賣建議，扣的是判斷力的分數。

**所有警示只陳述事實，不給行動建議。** 這條要寫進 README，是主動加分項。

### 警示層級與閾值

| 層級 | 顏色 | 觸發條件 | 顯示方式 |
|---|---|---|---|
| 🔴 **阻斷** | 錯誤色 | 餘額不足、持股不足、標的停止交易 | 表單錯誤 ＋ 停用送出鈕 ＋ **顯示差額** |
| 🟠 **提醒** | 警告色 | 報價中斷、單一持倉佔比 > 40% | 頂部橫幅／列表旁小標籤 |
| 🔵 **資訊** | 次要色 | 報價延遲（`stale`）、資料為前一日 | 小字註記 |
| 🟢 **正向** | 成功色 | 下單成功、股利入帳 | Toast ＋ 結果頁 |

> **集中度提示（> 40%）的措辭要特別小心**：顯示「台積電佔投組 45%」是陳述事實 ✅；顯示「持股過度集中」帶有評價意味，遊走邊界 ⚠️；顯示「建議分散」是投資建議 ❌。

### 錯誤顯示的三個層級

| 範圍 | 用法 | 元件 |
|---|---|---|
| 欄位級 | 輸入格式錯誤、數量超過可用 | 欄位下方紅字 |
| 區塊級 | 某個區塊載入失敗（如走勢圖） | 該區塊顯示 `ErrorState` ＋ 重試鈕，**其他區塊正常** |
| 頁面級 | 認證失效、5xx | 全頁 `ErrorState` ＋ traceId |

> **區塊級降級是重點。** 走勢圖掛了不該讓整頁白掉 —— 持倉列表仍然有價值。這需要在每個資料區塊獨立包 error boundary。

## 智慧摘要模板

在總覽頁頂部用一句自然語言說出重點。**只陳述事實，不做建議。**

### 模板

| 情境 | 模板 | 範例 |
|---|---|---|
| 一般 | `本月資產{變化方向} {百分比}，目前總值 {金額}` | `本月資產成長 3.2%，目前總值 NT$ 1,032,450` |
| 有主要貢獻 | `⋯⋯，主要來自 {標的名}（{報酬率}）` | `⋯⋯，主要來自台積電（+8.1%）` |
| 持平 | `本月資產大致持平，目前總值 {金額}` | 變化 < 0.5% 時使用 |
| 新帳戶 | `帳戶已開立，尚無交易紀錄` | `new-user` 情境 |
| 報價中斷 | `報價連線中斷，以下數值為 {時間} 的最後價格` | 降級提示 |

### 產生規則

1. **主要貢獻者判定**：對總損益貢獻絕對值最大的持倉，且貢獻佔比 > 30% 才提及
2. **變化方向措辭**：成長／下跌／大致持平（閾值 ±0.5%）
3. **不使用評價性詞彙**：不用「表現優異」「表現不佳」「值得注意」
4. **資料不足時不硬湊**：少於 7 天資料就只顯示總值，不講變化

## 替代方案與不選的理由

| 我們的選擇 | 沒選的方案 | 捨棄理由 |
|---|---|---|
| 三重編碼（色＋符號＋正負號） | 只用顏色 | 8% 男性有紅綠色覺辨識障礙 |
| Token 命名 `up`/`down` | `red`/`green` | 台股紅漲、美股綠漲，命名綁死顏色就無法切換市場 |
| 未實現損益前端算 | 後端每 tick 重算 | 頻寬與運算成本高，且推送延遲讓數字卡頓 |
| 相對時間 | 絕對時間戳 | 使用者關心「多久以前」；詳情頁才給完整時間 |
| `0` 顯示為 `NT$ 0` | 顯示為 `—` | 「餘額是零」與「不知道餘額」是不同的事 |
| 走勢用折線圖 | 面積圖 | 面積圖強調累積量，資產總值是狀態 |
| Y 軸不從 0 起 | 從 0 起 | 資產在百萬上下波動，從 0 起會壓扁成直線 |
| 配置用橫條 | 圓餅圖 | 中文標籤在圓餅外圍會擠；手機寬度利用率差 |
| 區塊級 error boundary | 頁面級 | 走勢圖掛掉不該讓持倉列表也消失 |
| 只做事實陳述 | 提供投資建議 | 投資建議涉及投顧特許業務，且是判斷力扣分項 |
