這份文件回答「做了哪些畫面、為什麼是這些」。技術層面見 [`00-architecture.md`](00-architecture.md)。

## 網站結構

```
App Shell（手機：底部 Tab Bar 3 項｜桌機 ≥1024px：頂部導覽）
│
├── /login                         登入（單一 demo 帳號）
│
├── /  →  轉向 /portfolio
│
├── /portfolio                     投資總覽  ★ 預設首頁
│   ├─ 總覽卡片                    總資產、今日損益、現金、持股市值、未實現／已實現損益
│   ├─ 資產走勢曲線                近 30 個交易日
│   └─ 持倉列表                    即時報價、現價、漲跌、未實現損益
│
├── /transactions                  交易明細
│   ├─ 類型篩選                    全部／買進／賣出／費用與稅／股利 → 同步至 URL
│   └─ 虛擬滾動列表                3,000–8,000 筆
│
├── /trade                         下單
│   ├── /trade                     步驟 1：選擇標的（搜尋）
│   ├── /trade/:symbol             步驟 2：填寫委託 ＋ 即時報價 ＋ 預估費用
│   ├── /trade/:symbol/confirm     步驟 3：確認（後端試算的實際費用）
│   └── /trade/:symbol/result      步驟 4：結果（帶 ?orderId=）
│
└── ⚙ Demo 控制台                  浮動面板，非路由
                                    狀態同步至 ?_demo_* 參數
```

### 幾個刻意的決定

| 決定 | 理由 |
|---|---|
| **總覽與持倉合併單頁** | 使用者的問題是「我現在有多少、賺賠多少」。分兩頁等於強迫他多點一次才能得到完整答案。詳見 [ADR 0007](adr/0007-merge-overview-and-positions.md) |
| **持倉不另開詳情頁** | 列表上已經有股數、均價、現價、市值、損益。再開一頁只是把同樣的數字放大 |
| **`/trade` 獨立於持倉** | 下單是完整流程，不是持倉的子動作。而且要能買「還沒持有的標的」 |
| **下單每一步都是獨立路由** | 返回鍵符合直覺；結果頁能用連結分享。但**表單資料不持久化** —— 下單草稿本來就不該被還原。詳見 [ADR 0008](adr/0008-order-step-in-url-data-in-memory.md) |
| **Demo 控制台不是路由** | 它是覆蓋在任何頁面上的工具。做成路由會讓人離開正在看的畫面 —— 而它的價值正是「一邊看著持倉頁，一邊打開報價中斷」 |

## 沒有做的畫面

| 原本規劃 | 為什麼沒做 |
|---|---|
| **智慧摘要** | 「一句話說出重點」很容易滑向投資建議，那是金管會的投顧特許業務。而且只陳述事實的摘要（「你的資產今天跌了 0.2%」）並沒有比上面那張卡片多說什麼 |
| **資產配置圓餅圖** | 與走勢曲線屬重複訊號 —— 兩個圖表講同一件事。持倉列表本身就是配置 |
| **日期區間篩選** | 類型篩選已經涵蓋主要使用情境（「這個月的手續費」）。日期區間需要一組 date picker，複雜度不成比例 |
| **明細日期分組** | 虛擬滾動下要處理 sticky header 的量測，成本高於收益。每一列已經有相對時間 |
| **持倉列展開** | 同上「不另開詳情頁」的理由 |

## 設計方向

### 使用者與裝置

| | 誰 | 決定了什麼 |
|---|---|---|
| **主要** | 25–45 歲上班族散戶，手機為主，通勤或睡前快速查看部位 | **Mobile-first**。桌機是放大版，不是主版型 |
| **次要** | 55 歲以上。字級小、金額看不清是主要抱怨來源 | 最小字級 16px、金額不用細字重、關鍵操作二次確認 |

### 三條硬性規則

1. **最小字級 16px，12px 禁用於任何數值** —— 為次要使用者。這會讓版面比一般 App 鬆，那是刻意的取捨
2. **所有數字用等寬（`tabular-nums`）** —— 表格中的金額才會小數點對齊
3. **漲跌用三重編碼**（顏色 ＋ 箭頭 ＋ 正負號）—— 紅綠色盲約占男性 8%，只靠顏色的話他們讀不出漲跌

### 錯誤狀態是主要內容，不是邊角案例

happy path 三秒就滑過去了。真正需要設計的是失敗：餘額不足長什麼樣、
下單逾時使用者怎麼知道成立了沒、報價斷了畫面會不會整片空白。

這也是 Demo 控制台存在的理由 —— 讓這些狀態能被一鍵重現，
而不是只在文件裡描述。
